# 사업 아이디어 추출

대화에서 사업화 가능한 아이디어만 걸러낸다. **거르는 게 일이지 모으는 게 일이 아니다.**

## 통과 기준 — 하드 게이트

아래 **셋이 전부** 대화에서 식별될 때만 통과한다. 하나라도 없으면 **탈락**이다.

1. **문제** — 누가 무엇 때문에 불편한가. "있으면 좋겠다"는 문제가 아니다
2. **대상 사용자** — 구체적으로 누구인가. "사람들", "개발자"는 대상이 아니다
3. **왜 지금** — 왜 지금 되는가. 기술이 최근 가능해졌거나, 본인들이 지금 이 문제를
   직접 겪고 있거나, 시장이 최근 열렸거나

세 칸을 채우려고 **추론하지 마라.** 대화에 없으면 없는 것이고, 없으면 탈락이다.
탈락한 후보도 사용자에게 "이건 왜 떨어졌는지" 한 줄로 보고한다.

## 근거 링크 필수

통과한 아이디어마다 **근거가 된 원문 메시지 링크를 반드시 붙인다.**
`get_conversation` 출력의 `⟨메시지ID⟩` 와 헤더 링크 틀로 만든다.
링크를 못 다는 아이디어는 대화에 근거가 없다는 뜻이므로 **탈락시킨다.**

## 절차

1. `get_conversation` 또는 `search_messages` 로 대상 대화를 가져온다
2. 후보를 추린 뒤 각 후보에 3요소 게이트를 적용한다
3. **노션 `아이디어` DB를 먼저 조회한다** — 같거나 비슷한 아이디어가 이미 있는지
4. 있으면 **새로 만들지 말고** 기존 항목의 `최근 언급` 을 갱신하고, 새로 나온 근거
   링크를 본문에 덧붙인다
5. 없으면 새 항목을 만든다
6. 노션에 쓰기 전에 **통과·탈락 목록을 사용자에게 보여주고 확인받는다**

## 노션 항목

| 속성 | 값 |
|---|---|
| 아이디어 | 한 줄 이름 |
| 문제 | 게이트 1 |
| 대상 사용자 | 게이트 2 |
| 왜 지금 | 게이트 3 |
| 상태 | 새 항목은 `발굴` |
| 출처 링크 | 근거 메시지 링크 |
| 발굴일 / 최근 언급 | 날짜 |

`상태` 는 사람이 관리한다. 에이전트가 `검토중`·`추진`·`기각` 으로 바꾸지 않는다.

## 하지 말 것

- 세 요소를 그럴듯하게 지어내서 게이트 통과시키기. **이 스킬이 막으려는 것이 정확히 이것이다**
- 잡담을 사업 아이템으로 포장하기
- 중복 확인 없이 새 항목 만들기 — 며칠이면 노션이 쓰레기장이 된다
- 확인 없이 노션에 쓰기
